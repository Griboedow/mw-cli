# Local patrol integration, 2026-10-17

Executed `tests/test_patrol_live.py` on the existing Windows XAMPP test wikis,
using Python 3.12.14 and real Bot Password API sessions:

| Endpoint | MediaWiki | Result |
| --- | --- | --- |
| `http://127.0.0.1/hoo/api.php` | 1.43.1 | Passed, 26.75 s |
| `http://127.0.0.1/hoo45/api.php` | 1.45.0 | Passed, 25.63 s |

The test used separate existing reviewer/editor accounts and short-lived random
Bot Password app IDs. Passwords were held in process environment/memory, not
committed. Site configuration, user passwords and group memberships were unchanged.

Verified against each server:

- Creation and subsequent edit by a non-autopatrolled editor appear in the queue.
- Page-filtered queue follows continuation with a one-item batch size.
- Creation review exposes full source; edit review compares the correct parent.
- Marking before reading configured guidelines is blocked.
- `--dry-run` leaves the edit in the queue.
- Marking by revision ID and by recent-change ID succeeds with a patrol token.
- Both changes disappear from the unpatrolled queue.
- The patrol log contains both revision IDs.

Unique test pages and their guidelines page were deleted in cleanup. Both temporary
Bot Passwords were removed on each installation. Normal deletion/patrol logs remain.
The runner exercised the actual Click command handlers and HTTP API; it did not
automate the browser. FlaggedRevs and Moderation approval were not tested or added.
